# VP-17686 — BestDeal total-drop poisons placerId (reconstructed record)

> Reconstructed by the 2026-08-19 dream closeout audit from the Jira description and
> PR #345. No STM was written during the work (done ~2026-08-12, same session cluster
> as VP-17685/VP-17691).

## What happened
- BestDeal silently drops some items: returns them in neither `left_over_test_id_list`
  nor `non_existing_test_ids`, `best_deal_price` 0.00. Deterministic. Single-item orders
  are fully exposed: one drop empties the order → eligibility gets `line_items: []` →
  upstream 400 → emr-v2 500.
- The throw escaped intake bookkeeping: `order_intake` row stayed `status='received'`,
  which is NOT in `RECLAIMABLE_STATUSES` (ineligible/rejected/dry_run/failed) → the
  partner's resend hit the duplicate short-circuit forever, `error` column empty.
- Upstream BestDeal defect belongs to the order team; deliberately NOT a dependency —
  emr-v2 must degrade correctly whatever BestDeal returns.

## Fix (PR #345 → staging 2026-08-12T19:41Z; → main via promotion #363 2026-08-14T01:36Z)
1. `accountBestDeal()` reconciles sent vs accounted (leftovers + each suggestion's
   zoomers/supplements); suggestion with both null = coverage unknown, no drop claimed.
2. Guard before eligibility: total drop → `no_orderable_items` rejection (422, reclaimable,
   dropped ids in errorCodes) + `[BESTDEAL_DROPPED_ITEMS]` warn on every drop;
   `patient_id` coerced to number (quoted id used to 400/500).
3. Enrichment throw → row marked `failed` (records cause, returns row to VP-17497 reclaim).
- Partial drop is logged but NOT blocked — blocking would change the shared HL7 path
  (product decision, left open).

## Closeout gaps (open as of 2026-08-19 audit)
