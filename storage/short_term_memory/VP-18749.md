## Approaches Considered
- Add `CalendarPrismaService` to `GetPatientTransService` constructor: rejected — the service is provided in 6 modules,
  3 of which (valogin/dashboard/setting) do not provide CalendarPrismaService; all 6 import `EventModule`.
- Chosen: new method on `EventService` (exported by EventModule) with `CalendarPrismaService` injected there; one
  provider line in `event.module.ts`, GetPatientTransService constructor untouched.
- Error path kept byte-identical: `getSamplesEventsInProcess` still resolves undefined on failure, so the pinned
  "C fails early" degradation (etd absent, active_event_id null) is unchanged.

## Lessons Learned
- Two scheduling systems coexist in calendar data: old MySQL `va_schedule` (sample_event/booked_schedule) and Postgres
  `calendar_prod` v2 tables. Any "is this accession booked" read must go to `v2_event_accession_claim`.
- `psql` masking with sed `s/:\/\/[^@]*@/` leaks when the password itself contains `@`; mask with a stricter pattern.
