# VP-18665 - Work Loop Record

## Ticket Analysis

### [2026-10-02 18:40] Facts (code + live staging core)

- Implemented scope (VP-18030, prod since 2026-09-01) = ACCOUNT/customer:
  customer path uses GetCustomerSamplesByTimeRange(customer_id); patient path
  filters `s.order.customerId === tokenCustomer` (order-list.service.ts
  listForPatient). Token carries both customer_id 3194 and clinic_id 125613;
  clinic_id is unused by the list.
- Portal clinic view rule (coreSamples patient.service.ts ~2887): order
  visible if order.clinic_id === viewed clinic (ANY customer) OR own order in
  own NPI clinics / clinic null / removed clinics. => Portal = clinic scope.
- The PM's verification example EXISTS on sandbox: clinic 125613 "Test
  Client, MD" has 57 customers; 35935 "Test AccountJan2025" placed 5 orders in
  clinic 125613 for patients 557149, 589232, 477769 (all also linked to 3194).
  Patient 557149 (Kang Bei): 3194 has 3 orders @125613 (+1 clinic null),
  35935 has 2 orders @125613 (2501276329, 2501276341). GET /orders?patientId=
  557149 with the 3194 token -> count 4 = only 3194's rows; the Portal clinic
  view would show 6. Same shape for 589232 (3 vs 4).
- Docs (mintlify list-orders) say "every order in your clinic" -> currently
  NOT true for multi-provider clinics. VP-18030 comment 186007 #2 asked this;
  Leo accepted account scope as launch semantics on 2026-09-01.
- Clinic scope would need: patient path = change filter to
  `order.clinicId === token.clinic_id || order.customerId === token` (data
  already in ListSamples block); customer path = NO clinic-scoped id source in
  v1 sample.proto (only Customer/Patient *SamplesByTimeRange); options are a
  new coreSamples RPC GetClinicSamplesByTimeRange (TS repo, mirrors the
  customer one with order.clinic_id) or fan-out over ListClinicCustomersByClinicID
  (57 customers here -> too many calls).

### Injected lesson (ENGINEERING-LESSONS, sparse k=1)

- "null = unknown != empty != false" (spec-page lesson, line 70): an
  explicit degraded/absent state must never be collapsed into a neighbouring
  one. Here: patient-exists-with-zero-orders (empty) vs patient-not-visible
  (not found) vs upstream-failed (unknown) are three states the list path
  currently folds into one 404.

## Approaches Considered

### [2026-10-02 18:45] Options for PM/Leo decision

- 1 (docs-only, zero code): keep account scope, change the docs to "orders
  placed by the authorized provider account", document that clinic-wide
  coverage is on the roadmap. Fastest, consistent with VP-17760 lookup.

  the customer path + both ConfigMaps untouched; docs stay as written. ~2
  PRs (coreSamples + emr-v2), needs core deploy first.

  account scope on the bare list until the core RPC exists; docs must state
  the asymmetry -> confusing, not recommended.

  must use the same relation (patient_customer vs clinic's customers).
