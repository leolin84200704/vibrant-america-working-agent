## Approaches Considered

### [2026-10-20] Proposed (pending Leo)
- Resolve accession -> sampleId -> ListSamples summary. If own order_intake row with that
  sample_id exists -> reuse the existing row path verbatim (identical object). Else in-scope by

  Not resolved / out of scope -> same ORDER_NOT_FOUND 404.

### [2026-10-21] PM answer narrows scope (Xiaoye OK'd both proposals, then Nan Wu overrode)
- Nan (comment 193137): "if the order is not placed by API, we can just return: 'Lookup and
  cancellation through the API only support orders placed via the API. This order was not placed
  using the API.' For other clinic, return 404 as now." -> supersedes ticket AC #4 (Portal coverage).
- Agent choices (not specified by Nan): HTTP 422 + code ORDER_NOT_PLACED_VIA_API (422 = understood,
  not served; matches intake/cancel "rejected" 422). "Not via API" = no order_intake row under the
  caller's customer_id -> another provider's API order in the same clinic also gets this message.
- Cancel needs no change: it accepts only orderId/placerId, which non-API orders don't have.
