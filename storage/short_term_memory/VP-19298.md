## Context
Bug from Xiaoye Li, 2026-11-11. Clinicians (practice 150105) changed Soonest Available Appointment to 1 h on 11/3,
but the Provider Portal still offers no same-day consult slots. PM Keith Lin, FE contact Zhiheng Wu, update goes to Mary Beth Augustine.

## Findings
### [2026-11-11]
- Root cause (FE): va-portal requests availability with start_date = moment().add(1,'days') in 4 calls:
  ScheduleMeetingDialogs.vue (new consult, ALL_CLINICIANS), ScheduleAMeetingDialog.vue x2 (getLabClinicianAvailability,
  reschedule SINGLE), MultiClinicianDialog.vue (reschedule ALL_CLINICIANS). Same-day slots are never requested.
- Backend LIS-transformer-v2 provider-availability.service.ts: getProviderAvailability uses the clinician's own
  v2_calendar.min_notice_minutes (:190), keeps slots after now + min_notice (:1126/:1156); validateSlotAvailability (:467)
  enforces the same at booking. No cache; FE queries are Apollo no-cache.
- The earliest slot in the host list comes from the gql first_available_slot, not the legacy firstAvailable REST.
- Calendar.vue / SelectTime.vue have no extra "past date" filter.
- Not verified: prod min_notice_minutes values for 150105 (calendar is Postgres; the vibrant mysql tool cannot reach it).
