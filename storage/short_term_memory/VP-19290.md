### Why the null id was not caught before FE hit it
1. I had the evidence and filed it in the wrong place. The inventory (179 vendor-NULL LIVE rows prod, 2 staging),
   the dry-run report ("ungroupable 207") and the close-out all named these rows, but only as "migration leaves them
   alone". I never followed them to the next consumer: what GET returns for them and whether the page can act.
2. Two artifacts I wrote contradicted each other and I did not cross-check: the view code documented null as
   "only while not migrated yet", the migration explicitly cannot migrate ungroupable rows -> null is permanent for them.
3. The unit test encoded the bug: `expect(...integrationId).toBeNull()` asserted the degraded state as correct.
   I tested what the code does, not what the consumer needs (an actionable key per entry).
4. Staging verification covered the happy path only (124546, every row has a vendor). The edge set the inventory
   surfaced (10136 in the staging dry-run ungroupable list) was never put through GET.
5. Worst: the FE plan first warned "integrationId null before migration, cannot suspend"; after prod migration I
   removed that line as obsolete, assuming null was gone. I deleted the only warning at the moment it became wrong.

## Lessons Learned
- A migration's residue set (rows it skips) must be walked through every consumer-facing read/action before done:
  "for each residue row, what does the API return and can the user act on it?"
- An id field in an API response that the UI must act on gets a never-null invariant test; a nullable key needs an
  explicit consumer path agreed with FE, not a doc comment.
- Staging verification must include at least one row from each edge class the data inventory surfaced, not only the
  happy-path practice.
- Do not remove a caveat from an outward plan without re-verifying the condition it described is actually gone.
- Related, same class: backfill template selection did not exclude test integrations (prod 10136 practice row copied
  the VP-17344 E2E "test folder only" row) -> template choice is also a consumer-facing decision. Left for Leo.
