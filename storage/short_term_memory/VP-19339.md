# VP-19339 - Healthie client ID on the patient record

## Context
- Epic VP-19337 (Healthie result delivery for JAG, PRD PH-976). Siblings: VP-19338 (delivery layer + Healthie adapter), VP-19340 (failures/resend), VP-19341 (FE field, Siyun), VP-19342 (JAG cutover). QA twin QH-8813.
- Healthie API needs its own client ID to put a PDF into a chart. JAG patients have numeric last names, placeholder DOB, no MRN, so match only on a stored ID.

## Decisions
### [2026-11-13] Leo
- Do NOT touch lis_core_v7 tables (no column on lis_core_v7.patient).
- Option 1 chosen over "JAG types Healthie ID into MRN": a mapping table in lis_emr owned by lis-backend-emr-v2 (Prisma schema.prisma, datasource lis_emr). Reason: manual MRN typing has no check and a typo sends PHI to the wrong chart; MRN has no clinic scope.
- Table must be created on prod manually before deploy (prod not Prisma-managed).
