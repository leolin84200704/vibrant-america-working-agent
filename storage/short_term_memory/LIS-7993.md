## Approaches Considered

### [2026-11-04 10:45]
- Data source: `lis_emr.hl7_file_input` on lisportalprod2 (read-only MCP + local mysql client, same creds as DailyJob/hl7_fail). One row per HL7 order file received on SFTP; success signal = `sample_id IS NOT NULL` (not `parse_finished`, 4 placed rows have parse_finished<>1; not `last_error`, which is never cleared on success).
- Server/session time zone is UTC; quarters assigned by `received_time` in UTC (boundary effect is a handful of files at most).
- Failure classes among never-placed rows: `customer_not_found` = ordering provider NPI has no LIVE+ordering `ehr_integrations` row; `emr_code_not_found LIKE 'VA%'/'discount%'` = test/bundle code not mapped; anything else = system error (gRPC call failed, NumberFormatException on "N/A" DOB, stranded files).
- Recovered-after-failure is only partly visible: Q1 (Java EMR-Backend era, pod `lis-emr-prod`) writes `''` to both flag columns on success and clears `customer_not_found` on re-parse; `last_error` exists since 2026-07-29 (VP-17533). So "placed after manual fix" is a lower bound for Q1/Q2 and complete only from 7/29.
- API channel = `lis_emr.order_intake`: 4 rows total in 2026, all customer 999997 (FHIR-API-TEST / E2E placer ids). No production partner credentials exist (memory: beta clients are sandbox-only). Report N/A.
- Internal-test exclusion: `order_input.clinic_id` only exists on emr-v2 rows (Q2 partial, Q3 all) and none hit clinic 10136 / QA test customers. Vendor test files identified by folder/file name: BIOINSIGHTS `/outgoing/` x3 (vibrant-test-order.hl7, V00000416, V00000417 = devcom tests, see INCIDENT-20261013) and NICHOLS `TestOrder.hl7` (id 6141, sample 2561718 customer 1999, later cancelled 09-01). ## Lessons Learned
- `hl7_file_input` ground truth for "order placed" is `sample_id`, not `parse_finished` (4 placed rows in 2026 have parse_finished 0/5) and not the flag columns (Java era wrote `''` on success).
- `sftpDir='problematic'` + pod `manual-processor` rows are re-run artefacts, not received orders; always exclude them from intake counts.
