- Redlock retryCount 10 x (200 ms + <=200 ms jitter) in BOTH services (LIS-Sample storage.service.ts onModuleInit, trans storage-legacy-import.service.ts) -> a loser keeps retrying ~2-4 s; the job finishes in ~0.5-1 s and releases -> the next pod acquires and runs again.
- Datadog 10-12..10-15: lis-sample-deployment (prod, 3 pods) logs "Start handling storage info from legacy system" 3x every day 16:15:00-16:15:02Z on 3 different hosts. Data upserts are idempotent (`update: {}`), but every run inserts one UPSERT_RECORD outbox event per legacy row -> each MACHINE event published 3x/day. Not introduced by trans; trans-st likely also re-ran on staging 10-14/15 invisibly (info logs dropped). Reported to Leo, not fixed (would change LIS-Sample behaviour).
