# VP-16163 - Work Loop Record

## Ticket Analysis

### [2026-10-23] Scope question: does "practice level" apply to all EMR orders, existing integrations included?
- Epic 10-08 decision text: "Integration moves fully to practice level. Since every order will now carry a
  practice ID, orders can be matched to the correct clinic directly." Quarantine (P3) and UniMod were dropped
  on that premise. Nothing in the epic or VP-19017 limits it to new integrations.
- Ground truth (emr-v2 main 4525ca1): only FOLLOWTHATPATIENT is in the practice-ID field map (ORC.17, Tom at
  Prospera confirmed in writing 10-08). Every other vendor orders by NPI in ORC-12 and resolves customer-level
  (provider-only, then a sort picks the row). 08-21 survey: 5 of 6 active vendors send no practice field.
  No other vendor confirmation found in STM / Jira.
- Result side is already practice-aware: VP-18755 (preview/manual/API) + VP-19019 (auto push, staging).
- Our data needs no migration: ehr_integrations is one row per (customer, clinic). Cost of "all practice level"
  falls on vendors: map every existing location to the Vibrant clinic_id and send it on every order. Trap:
  the MSH-6 value we send on results is not always clinic_id (~294/809 rows differ, VP-16793, now Inactive),
  so vendors' existing MSH-6 mapping is not a practice-ID mapping.
- Outcome only changes for providers with >1 practice under the same vendor (10-08: only 43262 Next Health).
- My proposal for the talk: existing integrations not forced; new integrations send practice ID from day 1;
  per-vendor switch via ORDER_PRACTICE_ID_FIELD_MAP; no reject-if-missing mode; NPI fallback when absent.

### [2026-10-23 16:12-16:17 PT] Slack with Xiaoye -- misunderstanding surfaced, parked to next week
- Xiaoye: recalled Junjie had talked with one vendor, and thought Leo had found that only that vendor was still
  active ordering with customer ID only.
- Leo corrected: it is NOT that only that vendor orders with customer_id. That vendor (FOLLOWTHATPATIENT) is the
  only one with a case of one practice_id mapping to multiple customers. All vendors today order by
  npi_number; essentially everything is customer-level.
- Junjie (who did the vendor outreach) is no longer at the company. Agreed to discuss next week.
- Implication: the PM's 10-08 premise ("every order will carry a practice ID") likely came from this
  misreading; the quarantine removal and VP-19017 scope may rest on it.

### [2026-10-23 16:21-16:41 PT] Slack with Junjie -- requirement clarified (Junjie is still at the company)
- Junjie wants the full integration list to notify every vendor: "only with all of them can we require practice id uniformly".
- Not a replacement: orders carry customer + practice ID, same as Portal. Who ordered is still the NPI; the practice ID only decides
  which practice the order belongs to. All vendors should send it.
- "Practice level" = the integration is owned by the practice: which EMR the practice uses and which providers may use it; every
  admin of the same practice sees the same data. Essentially a membership table.
- Only clinic_admin can add providers; any admin of the same practice can. The provider cannot add themselves.
