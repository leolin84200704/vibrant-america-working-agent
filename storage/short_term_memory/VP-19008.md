### [2026-10-27 17:00] Root cause: why bookmarkPagePdfDownload has no classic
- LIS-Report `base-report-server/src/pdf/pdf.controller.ts:208` declares no `style` query; it calls `printPDFByBarcodeWithBookmarkAndSections(...)` without one. The service (`pdf.service.ts:495`) already takes `style` (added be748efa 2025-04-30, kept in 1018a8a3 LIS-5726) but only appends `&&style=classic` when `type === 'AllClassicReport'`; `reportBase` is `this.base` on both branches. Classic is reachable only as the whole-order `type=AllClassicReport` (what pdf-cache uses).
- Frontend `report-pdf` already supports single-type classic: `/#/printable/{short}/{barcode}?...&style=classic` -> HomeView `reportStyle` -> service `getPDFInfo(type, acc, style)` -> `/result/resultinfo?...&&style=classic` (marketing downloader uses this URL shape).
- Live probes (pre=true, 2609166115): `type=AllClassicReport` -> 17 pp, 3,593,420 B, classic-only lines 198 / advanced-only 3 (= classic). `type=TTS` -> 5 pp, advanced.
- Proposed fix: controller `@Query('style')` passed through; service `stylePara` when `AllClassicReport || style === 'classic'`. emr-v2 then maps report_option -> style in fetchReportPdf, making style orthogonal to split. Open: classic TTB group should probably request classic `TTS` rather than merge three classic singles; verify on staging.
