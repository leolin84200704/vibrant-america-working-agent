# VP-19006 EMR: per-order kit delivery method in HL7 orders (Prospera / FOLLOWTHATPATIENT)

## Context
- PH-947 (Junjie, PM): two optional HL7 fields (blood / non-blood kit delivery), fall back to ehr_integrations.kit_delivery_option, fail on invalid value / non-blood office + Patient Pay Later / ship-to-patient with bad address (PH-943); Slack bot on every new failure; add to standard HL7 spec. Out of scope: failure feedback to EMR.
- VP-19007 = pre-release list of practices hit by the payment rule.

## Findings (2026-10-23)
- Payment IS per order in HL7: parser.service.ts chargeMethodFromIn1 -> IN1-2.1 == 'C' customerPay, anything else / no IN1 -> patientPayLater. There is NO integration-level default payment method. Leo initially read the "payment conflict" as unclear for this reason.
- Kit delivery today: kitDeliveryMethodsFor(customerInfo.kit_delivery_option) in parser.service.ts assembleOrderFrontend (~line 925). Non-blood resolves to office for NO_DELIVERY and BLOOD_ONLY.
- Parser reads no Z segment (grep src). Prospera (vendor 44) last 12 prod orders: only MSH/PID/IN1/ORC/OBR, all `IN1|1|C`, MSH v2.3, PID-11 address.
- Raw inbound HL7 not in DB: pulled from vendor SFTP `/Prod/FollowThatPatient/Order/archive` (read-only script in session scratchpad, creds from ehr_vendors).
- vibrant MCP (192.168.60.8:8800) port closed even on VPN (emr-v2 NodePort reachable) -> MCP server itself down. Direct read-only mysql2 via emr-v2 .env works (patterns.md recipe).

## Design decision (posted to Jira comment 193465, 2026-10-23, Leo asked to note on ticket)
- New Z segment `ZKD|1|<blood>|<nonblood>`, values SHIP_TO_PATIENT / SUPPLIED_BY_OFFICE, case-insensitive, empty = default, >1 ZKD = fail.
- Reason codes: KIT_DELIVERY_INVALID_VALUE / _MULTIPLE_ZKD / _PAYMENT_CONFLICT / _ADDRESS_INVALID.
- Spec addendum: emr-v2 `docs/hl7-order-spec-kit-delivery.md`, branch feature/leo/VP-19006 (worktree lis-backend-emr-v2.worktrees/VP-19006, off origin/staging 2cc097a), commit ba2f6e4 pushed. No PR yet.

## Decisions (Leo 2026-10-23)
- Payment check skipped when the order has no non-blood kit (portal isPatientPayLaterEligible parity: containNonBlood && nonBlood==suppliedByClient).
- JSON order intake: out of scope.
- Address check ONLY for orders carrying ZKD (AC5 vs req 6 conflict). Limits: missing street/city/state/zip + City <= 45 UTF-8 bytes; rest waits for PH-943 (Yuchen) shared definition.
