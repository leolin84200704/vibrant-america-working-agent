## Approaches Considered

### [2026-10-12 11:40 PT] Debate (PRO/CON fork agents) synthesis
- **A (recommended)** — mirror LIS-Sample PR #206: grpc-js client `Interceptor` attached in both `createClient` switches for Core V1 names (sample/customer/patient/referenceRange/contact/clinic + Cloud twins) and all six v2 clients; NOT testResult*/shipping*. `OAuth2TokenService.getAccessToken(alg)` gains per-alg cache/in-flight/cooldown and posts `algorithm=RS256`. Interceptor `start()`: if `CORE_RPC_RS256=off` -> HS256; else RS256, fall back to HS256 on failure; both fail -> omit authorization, counted WARN + damped Sentry; add `x-request-id` when absent; then `next(metadata, listener)`. `GrpcClientV2Service` gets `@Optional() oauth2Token`.
- **B (rejected)** — `await buildCoreMetadata()` at ~35 call sites, many inside `new Promise` executors; more diff, easy to miss a site.
- PRO verified: grpc-js parks `sendMessage`/`halfClose` while `processingMetadata` (client-interceptors.js 56-112), `options.interceptors` is consumed by the client ctor (client.js:45) and coexists with channel args; must not pass `interceptor_providers`.
- CON risks adopted: (1) the per-call deadline timer starts before `start()` runs (resolving-call.js:44-79) -> cap the token wait (3s `Promise.race`; fetch continues to warm the cache) and pre-warm at client init; (2) wrap the whole `start` body in try/catch — a sync throw inside an interceptor escapes `makeUnaryRequest` and would leave `new Promise` call sites pending forever; (3) cloud+on-prem fallback = two clients = token asked twice per logical call (cache makes it cheap; counter double-counts a double miss — documented); (4) scope is a name list -> add a construction-time coverage spec; (5) `internal_user_name:"trans v2"` identity cannot be fixed here — surface to Leo.
- Staging caveat: staging emr-v2 ConfigMap points GRPC_V2_* at 10.224.0.10:32100 = the PROD coresamples-v2 NodePort, and both envs send service-name `lis-backend-emr-v2-production` -> a staging smoke shows up in prod Core's token_check; distinguish by method + timestamp.
