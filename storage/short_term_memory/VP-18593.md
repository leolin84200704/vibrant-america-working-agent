# VP-18593 - Work Loop Record

## Ticket Analysis

### [2026-09-30 17:20] Origin
Leo, after VP-18589: 「我們tracking status 是直接接fedex? carrier、shippedAt、deliveredAt
感覺應該要有？」 then 「要，這是嚴重的問題。請改善，doc + comment也要改」.

Four-part:
1. 目的 — the documented kit block (carrier / trackingNumber / shippedAt / deliveredAt)
   was cut to status + trackingNumber on 08-13 (VP-17760 c.183880/183942) as "no
   upstream has them". Wrong for two of three.
2. 改前 — LIS-Shipping origin/master: FedEx EDI status feed → Azure Service Bus
   (`handleFedexTrackingUpdates`) → `fedex_tracking_updates` + `client_transaction_shipping`
   (kit_status, current_status = FedEx text, fedex_delivery_date); raw FedEx events in
   prisma8 `fedex_shipping_status` (last_status_code PU/DL…, delivery_date/time,
   delivery_attempt_exception); DHL in `dhl_tracking_events`. `queryKitStatus` builds
   `Packages.url` by its own rule (12-digit → fedex.com, 10-digit → dhl.com) and
   `pickup_time` = `retrieveTrackingPickupTime` (earliest PU scan, LA-local → UTC ISO)
   || po_create_time. Proto field 5 `pickup_time` exists in LIS-Shipping /
   LIS-transformer / cloud-local-proxy protos; emr-v2's two copies had 4 fields →
   proto-loader dropped it. Delivery time is in the DB but NOT in the RPC.
3. 改後為何有效 — read url + pickup_time; carrier from the URL host (single source of
   truth = shipping's rule); shippedAt only once rank ≥ 1 (READY's pickup_time is just
   the PO create time). deliveredAt stays null until shipping extends the RPC.
4. 改什麼 — see Code Changes.

Docs: mintlify already documents all five fields (that page was never updated for the
08-13 cut); Confluence 2485977089 v24 (today, VP-18589) says the three were dropped —
must be corrected again to "carrier + shippedAt live, deliveredAt pending shipping".

## Approaches Considered
- Carrier from tracking-number length in emr-v2 — rejected: duplicates shipping's rule
  (VP-17760 comment already warned URL/number pattern-matching drifts). Reading the
  host of the URL shipping built keeps one owner.
- Synthesize deliveredAt from core / list signals — rejected: no timestamp anywhere we
  reach; null + doc note + shipping ask.
