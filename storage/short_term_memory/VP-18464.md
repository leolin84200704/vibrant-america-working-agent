- Capture v1 (kubectl logs -f, 06:19Z-19:14Z) was NOT gap-free: (a) `kubectl logs -l <selector>` defaults to `--tail=10`, so every reattach

  matches by `<timestamp> <nginx request id>` via `seen.ids` (awk BEGIN getline; the two-file `NR==FNR` idiom silently swallows stdin when
  the ids file is empty -- hit that, fixed), heartbeat = one line per poll `<poll time> <lines in window>`. Verified: direct count default

  starts 2026-10-06 19:15Z; earliest 30 days = 2026-11-05 (unchanged date).
- Lessons: `kubectl logs` with a label selector silently caps at 10 lines unless `--tail=-1`; a follow stream is not a retention mechanism,
  poll with overlap + dedupe instead; and verify a capture by comparing its first window against an independent direct count.
