## Lessons
- `sftp_archive_path` on ehr_integrations is dead weight for the result push: nothing on the push path reads it. When comparing sibling rows for "will the folder change", the only destination inputs are `sftp_result_path`, `use_vendor_sftp_config` (+ vendor row) or the row's own host/user, `legacy_emr_service`, `pipeline_location`.
- VP-16617-style bulk audits that touch `updated_at` on sibling LIVE rows can silently flip which sibling the listener's `[integration_type desc, updated_at desc]` sort + first-wins dedupe picks (this ticket: PERSONALIZED -> CLASSIC on 2026-05-14). Bulk updates to ehr_integrations should leave `updated_at` alone or be followed by a sibling-conflict query.
