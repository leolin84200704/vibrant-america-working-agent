## Lessons
- Restarting the emr-v2 prod pod wipes the sidecar Redis -> delayed/retrying BullMQ jobs vanish silently. Before a
  restart, list delayed/failed jobs; after, repush them.
- GetResultStatus returns only the latest transmission record of the sample, not per integration -> a TRANSMITTED
  can be another vendor's copy.
- gRPC/HTTP GenerateResultHl7 fans out to every distinct destination with no dedup and no integration_id field ->
  for multi-integration samples, enqueue a BullMQ job with integration_id instead.
