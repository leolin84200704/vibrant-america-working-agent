## Approaches Considered

### [2026-09-30 12:40]
- **Probe addendum (on-prem fallback 192.168.60.6:30600)**: garbage Bearer is NOT blocked (sample 2600000 OK with `Bearer not.a.jwt`) -> on-prem lis-test-connect runs an older image without MetadataLoggerInterceptor; adding a token cannot break the fallback. Side finding: on-prem returns `Internal server error` for real samples 2555493 / 2641983 regardless of auth (cloud returns 467 / 99 tests) -> on-prem fallback is unhealthy today, independent of this ticket.
- **A (recommended, minimal)**: new `OAuth2TokenService` (ConfigService `OAUTH2_*`, cache with 5-min safety, in-flight dedup, 10s fetch timeout, 60s negative cache, throws when no token) injected `@Optional()` into `GrpcClientService`; one `buildResultsGrpcMetadata()` used by both results call sites (metadata is already built per attempt): service-name + x-request-id (randomUUID) + authorization when a token is available. Fail-open = omit authorization, WARN + damped Sentry message with running counter (emr-v2 has Sentry, no Datadog metrics). On RPC error `Invalid authorization token` -> clear token cache so the next attempt mints fresh. ShortcutService untouched (follow-up dedupe).
- **B**: A + ShortcutService delegates to the shared service (PRO: one cache per process, removes duplicate minting; CON: order-intake blast radius, scope creep, reviewer rejected over-built PRs before) -> not recommended for this PR.
- **C**: sibling convention npm `vibrant-oauth2-client` (VIBRANT_CLIENT_ID/SECRET, process.env only) + strict-by-default with GRPC_OAUTH_FAIL_OPEN -> needs new ConfigMap keys in both clusters and a second OAuth client identity in the same pod; strict default turns an OAuth outage into results not delivered while the server does not even require the token -> rejected.
- **Debate synthesis**: PRO insisted on `@Optional()` injection (4 specs `new GrpcClientService()` zero-arg) and on probing on-prem (done). CON insisted on mint-per-attempt (already the case), cache drop on auth reject (adopted), fail-open must be observable (adopted via Sentry), do not touch ShortcutService (adopted), x-request-id explicit (kept, flagged to Leo).
- **Lesson followed**: fail-open gate gets a counter (ENGINEERING-LESSONS 29); verified live, not mock (probe both endpoints, grader validated with garbage token).
