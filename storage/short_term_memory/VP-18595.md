# VP-18595 - Work Loop Record

## Ticket Analysis
1. 目的 — stop reporting kit_delivered for kits that never arrived.
2. 改前 — deriveOrderStatus: `outbound PATIENT_RECEIVED_KIT || returned READY_FOR_RETURN_SHIPMENT → kit_delivered`, checked before LAB_SHIPPED_KIT. VP-17760 comment 183880 assumed READY_FOR_RETURN = "patient has it, hasn't posted it yet". Live prod 874611616610 (sample 2598251): outbound DELIVERY_EXCEPTION, never delivered; return 792558624460 already READY_FOR_RETURN_SHIPMENT → status kit_delivered while kit.status = shipped. Return labels are printed with the PO.
3. 改後為何有效 — the outbound package is the only evidence of delivery when one exists; READY_FOR_RETURN counts only for orders with zero outbound packages (in-clinic handoff).
4. 改什麼 — one condition in order-status.derivation.ts + a six-case test matrix.

## Approaches Considered
- Drop the READY_FOR_RETURN rule entirely — rejected: in-clinic handoff orders have no outbound package and would floor to placed.
- Use GetTrackingDetails delivery scan to decide delivered — out of scope (VP-18593 deliberately keeps status = shipping's kit_status).
