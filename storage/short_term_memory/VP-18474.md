## Approaches Considered
- 4-part (lis-prod-change-gate Gate 1):
  1. 目的: finish VP-18474 — trans must not call core v1 HTTP after 10-31; remove the last code path and the dead config so a future "key missing" cannot silently route anything back through core v1.
  2. 改前: trans v1 exposes `GET /utility/login` which forwards a session cookie to core v1 `/api/user/login_via_session/`; nobody calls either end (15 d). The other three call sites already go to core v2 gRPC (VP-18152). Five ConfigMap keys remain on prod + st, unread except `LOG_IN_VIA_SESSION`.
  3. 改後為何有效: deleting the route + service method + env read leaves zero `lis-core-http-service` references in trans; deleting the keys makes the ConfigMap match the code and removes a never-expiring admin JWT from cluster config.
  4. 改什麼: (a) LIS-transformer PR: remove `@Get('/login')` handler, `UtilityService.login()`, the `LOG_IN_VIA_SESSION` env read (+ a spec asserting the controller no longer exposes `login`); dual-track main + stage_test. (b) ConfigMap: `kubectl patch --type=json` remove the 4 VP-18152 keys now (prod + st), `LOG_IN_VIA_SESSION` after the PR is deployed. (c) Two-week zero check on 10-14 (VP-18140 log), then Dev Complete.
- Alternative considered: leave `GET /login` and only drop keys — rejected: the env read would then throw at call time instead of 404, and the route is dead by every measure.
