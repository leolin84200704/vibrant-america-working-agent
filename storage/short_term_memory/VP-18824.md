- 目的: Cerbo folders must contain only `.hl7`; the PDF stays embedded (it already is).

  `deliverOrderSummaryPdf` (VP-18138, `:1103`) is the other loose-file path; MDHQ vendor has it 0.
- 改後為何有效: with split OFF the attachment hook returns before any upload; the push is exactly
  the pre-09-25 shape that Cerbo ingested within hours for months.
- 改什麼: see A/B below.

**A. Config rollback (the documented VP-18194 rollback)** — prod
`UPDATE ehr_integrations SET split_result_pdf_by_report = NULL WHERE id='cms56tk180041t807p7tt9nxm'
 AND clinic_id=127660 AND split_result_pdf_by_report = 1` (1 row). No deploy, effective on the next
push (60 s destination cache only matters when the row is NULL and another row is split=1 — none).
Rollback-of-rollback = set it back to 1. Verification: Gate 7 reverse audit (whole-table count of
non-NULL = 0), consumer readback via the deployed `report-pdf-settings.js` in the pod, and the
real round-trip = next Maristany HL7 appears in `/results/archive/` with a Cerbo suffix within hours
and NO `.pdf` beside it.

**B. Code guard so a Cerbo folder can never receive loose files again** — new
`ehr_vendors.sftp_accepts_loose_files` (TINYINT(1) NOT NULL DEFAULT 1; set 0 for vendor 1 MDHQ).
Both loose-file paths (`deliverOrderSummaryPdf`, `deliverReportPdfAttachments`) skip with one WARN
when the vendor says 0, regardless of integration/vendor split flags; `resolveReportPdfDelivery`
then also forces `deliverCombined=true` for such a vendor so "split on + combined off" cannot strip
the embedded PDF for an HL7-only partner. Pure-function seam (`report-pdf-settings.ts`) => behavior
tests without mocks; service-level test asserts no `uploadHL7Files` call. Cost: DDL on prod BEFORE
deploy (Gate 3, ADD COLUMN NULL-safe default, INSTANT), PR -> staging -> main. Why worth it: PM
asked twice to enable this practice; the MDHQ vendor row covers 202 practices and one data edit
there would stall 202 pollers. Without B the invariant lives only in people's memory.

**C. The per-report feature Cerbo CAN consume = N PDFs embedded in the HL7** (VP-18194 option C,
rejected then as "Cerbo must confirm"): `Hl7ResultData.pdfReport` -> array, one ED OBX per report
under its own OBR, shared encoder path for every vendor. Not a 10-16 bug fix; needs Cerbo's written
spec on multiple PDF OBX before any code. => raise to PM as the follow-up decision, not this ticket.

Rejected: repush of the 12 stalled orders (Cerbo ingested them 10-13 20:14Z; Leo's cross-ticket
