# VP-19015 VI My Calendar: recurring events 1h off after DST ends (11/02)

## Findings

### [2026-10-23 15:00] Root cause (verified in code + calendar_prod)
- LIS-transformer-v2 `src/calendar/models/event/event.service.ts`:
  - `expandRecurringEvent` (~L3933) runs `RRule.fromString(event.rrule).between()` on a UTC DTSTART with no TZID -> occurrences keep a fixed UTC time.
  - `combineOccurrenceDateWithEventTime` (L2772) glues occurrence UTC date + original UTC time-of-day -> same fixed-UTC result.
  - Same pattern in `provider-availability.service.ts` `doesRecurringEventConflict` (~L523) -> consult availability blocked at the shifted hour (Nour's 11:30-12:30 ET case), plus meeting-request, daily-report, public-booking, task.
- ehr-frontend `ScheduleAppointmentPanel.vue` createEvent/updateEvent payload (~L809) sends no `timezone`; backend defaults `timezone: input.timezone || 'UTC'` (L507). Google sync uses `event.timezone || 'UTC'` -> synced copies also shift.
- Frontend `buildRrule` emits `DTSTART=<utc>Z`, BYDAY from local date (latent wrong-weekday bug when local evening crosses UTC midnight).
- calendar_prod: live recurring series reaching past 11/01: 43 with timezone='UTC' (all creator practice 150105), 10 America/Los_Angeles. Exceptions with recurrence_id after DST on UTC events: 0 (as of 2026-10-23).
