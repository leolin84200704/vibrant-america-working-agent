### [2026-09-08 12:30] Options
- **A (recommended): emr-v2 in-job post-put attachment.** After `{accession}.hl7` TRANSMITTED, if
  `integration.ehr_vendor.deliver_order_summary_pdf` (new column, default 0, set 1 for vendor 44),

  `sftpService.uploadHL7File` to same folder; record attempt in NEW append-only table
  `result_attachment_records` (record_id, sample_id, accession, attachment_type, file_name,
  status, error, http_status, duration_ms, created_at). Non-fatal like ChARM block. Whole-order
  pushes only (push_scope_key NULL). Re-drop on every push.
- B: separate sweeper/BullMQ job that backfills PDFs for TRANSMITTED records lacking an attachment.
  CON side's preferred. Decoupled + own retry, but a second scheduler/state machine; PDF arrives
  minutes after HL7. Kept as Phase-2 retry path over the same table if A's failure rate warrants.
- C: order-management pushes the PDF itself — rejected (no SFTP/integration knowledge, breaks single
  outbound exit).
- D: second OBX ED segment inside the HL7 — rejected (customer asked for a separate PDF file;
  VP-17812 Q2 answer).
- E: env allowlist `ORDER_SUMMARY_PDF_VENDOR_CODES` instead of vendor column — zero schema risk but
  deploy-to-change and invisible to ops; offered as fallback if Leo wants no ALTER on ehr_vendors.

### Debate synthesis (PRO vs CON agents)
- Accepted from CON: (1) attachment status must feed the daily result_fail triage query, otherwise
  "non-fatal" = invisible; (2) PDF step needs its own hard 30s cap (job hard timeout 10 min already
  over-subscribed by 180s x 4 report-PDF retries) — a job-level timeout would re-push the HL7 5x;
  (3) new append-only table instead of 3 columns on result_transmission_records — no read-failure
  blast radius if deploy precedes ALTER, survives 24h record reuse, keeps per-attempt history;
  (4) confirm filename pattern / folder behavior with Prospera in writing (already a ticket open
  item) and have PM eyeball a Go-rendered PDF vs the legacy-Java sample they showed the customer;
  (5) hung-fetch spec + staging round-trip with `%PDF-` magic check.
- Kept from PRO: in-job over sweeper (ordering invariant free, ChARM precedent, no new scheduler);
  vendor-level flag (33 rows one folder; future franchises correct by construction);
  `{accession}_ordersummary.pdf` (prefix pairs with .hl7, suffix names the doc type);
  re-drop every push (document is a function of order state; idempotent overwrite).
- Residual risk accepted: `ehr_vendors` column ALTER must precede deploy on staging+prod (hot lesson
  "Schema migration before deploy"); additive nullable/default column, same pattern as
  gz_ny_routing_enabled / deferred_report_short_names.
