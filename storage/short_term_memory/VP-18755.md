# VP-18755 - Work Loop Record

## Ticket Analysis

### Why it exists (2026-10-08)
Leo asked what is left to make resolution clinic-level everywhere after VP-17827. Code read on main 73e3459:
- `result-generation.service.ts` `validateEmrIntegration(customerId, clinicIds)`: findFirst by customer_id only (orderBy
  integration_type desc); sample clinic ids used only when the customer has NO row (then customer_id='-1' rows).
  `findDistinctEligibleResultIntegrations`: findMany by customer (type desc, updated_at desc), dedupe by
  (legacy_emr_service, sftp_result_path) keeping the first -> for Next Health 43262 (4 rows, same vendor + path) the
  kept row is the recency winner, whose `msh06_receiving_facility` is a clinic id -> wrong MSH-6 possible.
  `getClientConfiguration(..., customerId, clinicId)`: same customer-only findFirst.
- `order-intake-enrichment.service.ts`: non-token provider -> `fetchById/fetchByNpi(providerId)` with no practice while
  `effectiveClinicId = ctx.clinicId`; kit_delivery_option / old_clinic_id came from the recency winner.
- `getSampleRelevantInfo` (grpc v2) returns `clinicIds` from core `clinic_ids` (list).
Prod blast radius today: exactly one multi-practice provider in all of prod (43262 @ FOLLOWTHATPATIENT).
