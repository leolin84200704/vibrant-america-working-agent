## Ticket Analysis
### [2026-09-14 11:20]
- Trigger: sample 2632218 (EverSpan Life, clinic 66839, customer 22376, MDHQ, 2026-09-09). Admin UI shows
  `kit_delivery_option=BOTH_BLOOD_AND_NON_BLOOD` but order_input has blood=suppliedByClient.
- Root cause: emr-v2 `customer-detail-fetcher.service.ts` reads `ehr_integrations.kits_options` (=0 for 22376)
  and `parser.service.ts` switches on it (1:1 port of Java ParseHL7.java:930). `kit_delivery_option` was never
  consumed at runtime; the admin UI edits `kit_delivery_option` only, so the two drifted.
- Java EMR-Backend order path is dead: every hl7_file_input row since 2026-08-01 (336 rows, MDHQ/THM/FTP) was
  processed by `lis-emr-v2-deployment-prod-*` pods. Java left untouched.

## Approaches Considered

## Decisions Made
- Leo 2026-09-14: "全部改成用 kit_delivery_option, 然後看一下有哪些是這兩個column不一樣的".
