# VP-18347 - Work Loop Record

## Decision: CRM, not LIS-Shipping — reasons
1. Both proxies (trans v1 `proxy.service.ts:219` and cloud-local-proxy `grpc.service.ts:203`) do the same two trivial things and nothing else: `comments = String(julien_barcode)`, forward the caller's token with the `Bearer ` scheme stripped, POST to `https://www.vibrant-america.com/crmapi/placepatientorders`. "Direct" = reproduce those two lines → the CRM receives identical bytes. Zero behaviour change, which is the program's rule.
2. LIS-Shipping `POST /orders` is a different request contract (`body_v2`, setting-consumer.controller.ts:8790-8820) and a different system of record for the order — a product decision that belongs to the shipping team, not to an optimization ticket.
3. The billing TODO's open question ("which identity does billing use") is moot for the CRM destination: whatever token billing sends today already reaches the CRM unchanged through the proxy.
