# MAIL-1227266978: re-push after the Cerberus SFTP outage

On 11-10 I closed VP-19290 and called the SFTP handshake timeouts on 45.24.217.155 a vendor-side problem. That was
wrong. The host is our own Cerberus server, and it stayed down until IT restarted the service on 11-12. The lesson is
to look up who owns an SFTP host before labelling a timeout as vendor-side; the label decided that nobody on our side
looked further.

Before the re-push I checked the transmission table for a later TRANSMITTED row on each sample, because a re-push on
top of a delivered file would send the vendor a duplicate. None existed. The RPC has no integration filter, so two
samples went to MDHQ a second time; that cost was known and accepted before running it.

Datadog showed nothing for the re-push. The grpcurl target is the on-prem prod NodePort, which does not ship logs to
Datadog, so the DB readback was the only usable evidence. Next time the plan's test step should name the evidence
source that matches the endpoint actually called.
